## 1. 结论摘要

整体方向是对的：信息架构清楚、三组导航稳定，表格/卡片/详情面板的交互模型统一，
空状态文案、字段说明 tooltip、复制到剪贴板、表单内联错误、选中行反色等细节都做过打磨。
**当前主要问题不是"不好看"，而是"危险动作不设防、失败反馈留不住、信息密度与文档承诺有落差"。**

| 维度 | 评分（5 分制） | 一句话 |
| --- | ---: | --- |
| 信息架构 | 4.5 | 监控 / 网关 / 系统三组清晰，页面职责不重叠 |
| 视觉一致性 | 4.0 | 间距、圆角、状态色统一；少量英文术语与货币符号不统一 |
| 交互安全 | 2.0 | 删除、轮换等不可逆操作无二次确认；一次性明文常驻窗口 |
| 反馈与状态 | 2.5 | 3 秒 flash 承担了全部异步反馈；失败信息会消失 |
| 首次使用 | 2.0 | 空状态只"告诉用户没有"，没有把下一步动作做成按钮 |
| 可观测性 | 3.5 | KPI、趋势、日志齐全；图表不可悬停读数，日志缺详情 |
| 键盘/无障碍 | 2.5 | 侧栏行可聚焦但 Enter 不触发；文档承诺的快捷键未实现 |
| 与 06 文档一致度 | 2.5 | 页面骨架到位，但实时尾巴、命令面板、账号用量、指纹页缺席 |

**建议优先级**：先补齐"防误删 + 一次性密钥可控 + 反馈留存"（P0），
再做"首启引导、空状态 CTA、日志详情、图表读数、快捷键"（P1），
最后处理文档差额与长期页面（P2）。

## 2. 高优先级问题（P0）

### P0-1 破坏性操作没有二次确认

**现象**：供应商、模型、路由模型、凭据、客户端密钥的删除，以及客户端密钥轮换，
在行内「更多」菜单里点一下立即执行；轮换会立刻让旧密钥失效。

**证据**

- `internal/desktop/state.go:572` `deleteProvider`、`:594` `deleteModel`、
  `:984` `deleteRoute`、`:1225` `deleteCredential`、`:1283` `deleteClientKey`
  全部直接调用 `s.run(...)`；
- `internal/desktop/state.go:1260` `rotateClientKey` 直接执行；
- `internal/desktop/pages_gateway.go:287-290`、`:443-458`、`:103-121`、
  `:837-852`、`:965-975` 的菜单项没有确认步骤。

**影响**：误触即不可逆；删除供应商会级联影响凭据/模型，删除被路由模型引用的模型
会被服务端 409 拒绝，但用户只看到 3 秒红字。

**建议**：统一接入 `ui.AlertDialog`，标题写明对象名，正文写"影响范围 + 不可撤销"，
按钮顺序「取消 / 删除」，默认焦点在「删除」。批量/级联删除必须列出受影响数量。

### P0-2 一次性明文密钥常驻窗口，且无法关闭

**现象**：创建或轮换密钥后，`createdToken` 一直显示在「新建客户端密钥」面板里，
没有关闭按钮；切换页面后仍然保留，只有下一次创建/轮换才会被覆盖。

**证据**

- `internal/desktop/state.go:1252`、`:1275` 只写入 `createdToken`，全项目没有清空点；
- `internal/desktop/pages_gateway.go:888-898` 提示条只有「复制」；
- 页面底部却写着「关闭提示后无法再次取回明文」，但界面没有"关闭提示"这个动作。

**影响**：肩窥/录屏风险；与安全文案自相矛盾。桌面端窗口长期开着时尤其明显。

**建议**：提示条增加「关闭」按钮；离开 `/keys` 页面自动清空；文案与行为一致。

### P0-3 日志轮询会清掉用户选中的行

**现象**：停留在请求日志页时每 5 秒 `reloadQuiet()`；`apply("/logs")` 无条件
`logSel = -1`，正在查看的行被取消选中，详情（本轮新增）无法停留。

**证据**

- `internal/desktop/desktop.go:99-112` 5 秒轮询 `/` 与 `/logs`；
- `internal/desktop/state.go:431-433` 每次应用日志数据都重置 `logSel`。

**建议**：刷新前后按请求 ID 保留选中行；行已滚出窗口才取消选中。

### P0-4 过滤/搜索存在请求竞态与被吞掉的筛选

**现象**

1. `load()` 在 `s.loading` 为真时直接返回（`state.go:250-253`）。用户在上一次加载
   未完成时改过滤器，新的筛选条件不会触发请求，界面停留在旧结果。
2. 后台 `fetch` 结果没有序号，慢请求后返回会覆盖快请求的新结果。
3. 模型搜索每敲一个字符就 `s.reload()`（`pages_gateway.go:351-353`），每次都有
   页头 spinner，输入体验抖动。
4. `fetch` 在后台 goroutine 里直接写 `s.adapters`（`state.go:304`），而 view 在主线程
   读它，属于数据竞争。

**建议**：引入请求序号（只应用最新一次）、允许筛选变更排队、模型搜索改为本地过滤；
适配器目录取回 `fetched` 后在主线程 `apply`。

### P0-5 失败反馈只活 3 秒

**现象**：`flash()` 3 秒后自动清空（`state.go:496-511`）。删除被 409 拒绝、探活失败、
保存需重启等信息都只显示 3 秒；用户离开页面或正在看别处时完全错过。

**证据**：`state.go:496-511`；页头状态 pill `view.go:200-206`。

**建议**：错误类 flash 不自动消失（或延长到 8 秒并提供关闭），成功类保持 3 秒；
写操作失败同时写入当前页的 `pageErr` 错误条，形成"页头提示 + 页面内持久错误"双层。

### P0-6 桌面壳从未绑定网关端口（实测客户端后补记，已修复）

**现象**：客户端请求 `GET http://127.0.0.1:3050/v1/models` 报 "could not reach"，
桌面窗口却显示「运行中 http://127.0.0.1:3050」。

**证据**：`app.New` 只准备不监听（`app.go` "It does not listen yet"），
`cmd/prune-server` 调用了 `Listen + Serve`，但 `desktop.Run` 从未调用——
窗口在跑、页脚在报地址，实际 3050 无任何监听。`ListenScanning` 的注释写着
"桌面壳使用它"，调用点却在 P7/P8 期间丢失。

**修复**（2026-11-08）：`desktop.Run` 启动时 `ListenScanning(cfg.Host, cfg.Port)`
+ `go Serve`，退出时 `Shutdown`；实际绑定地址进入 `uiState.boundHost/boundPort`，
页脚/侧栏/引导卡/托盘复制的地址一律以它为准；端口漂移（默认被占自动 +1）时
flash 提示；Serve 异常退出时界面提示而非静默。

**教训**：UI 显示「运行中」之前，必须有真实证据（绑定成功）。状态展示与真实
状态的偏差是最危险的一类 UI 缺陷——它把基础设施故障伪装成客户端配置问题。

### P0-7 每个完整流式请求都被记为 502（实测客户端后补记，已修复）

**现象**：客户端经网关的流式对话全部失败；请求日志显示自相矛盾的记录——
`finish_reason=tool_calls`（流完整走完）却 `状态=502`、`错误类型=upstream_stream_error`。

**证据**：`StreamDecoder` 契约规定「完整结束时返回 `io.EOF`」（`codec/stream_test.go`
如此断言），但 `relay.go` 的流式循环对任何非 nil 错误一律当作上游失败：向客户端
流内注入 502 错误事件、落库 502。**每一个正常完成的流都被判死刑**。既有测试没拦住，
因为流式响应头早已发出（HTTP 状态恒 200），测试只断言了 `[DONE]` 与文本拼接，
把注入的错误行当解析失败跳过。

**修复**（2026-11-08）：

- `relay.go` 将 `io.EOF` 视为流的正常终点；真实上游错误（截断/连接断/协议错）
  行为不变——仍 502 + 流内错误（红线「不谎报完成」不受影响）；
- 补上观测缺口：真实上游流错误现在写 warn 日志（provider/model/原因），
  「为什么 502」不再无处可查；
- 回归测试双向锁定：完整流必须 200 落库且流内无错误事件
  （`TestChatCompletionStreaming` 强化），截断流必须仍 502
  （`TestChatCompletionStreamTruncatedStillFails`）。

**教训**：截断流的判定特征是「无 finish_reason」；「有 finish_reason 却 502」
本身就是网关 bug 的指纹。状态机两端的契约（io.EOF=结束）必须在接线处再验一次，
不能只信单侧测试。

### P0-8 有内容但缺 finish 的流被记成 200（实测客户端后补记，已修复）

**现象**：客户端报 "Stream ended without finish_reason" 并自动重试（2/5），
网关日志里同一条请求却是 `200`、输出 949 token、无完成原因——上游
（OpenAI 协议）流式吐出内容后没发 finish_reason 就断了流。

**证据**：relay 流结束分支的条件是 `finish == "" && !sentAnything`——只有
「一个字都没发」才算失败；**发过内容的缺-finish 截断被记成 200 并照常 [DONE]**。
P0-7 修复没暴露它，因为 CC 适配器在 EOF 时自己报 ErrTruncated（502），
而 openai/anthropic 编解码路径会"干净地"EOF——缺口只在 OpenAI 协议上游出现。

**修复**（2026-11-08）：`finish == ""` 一律视为截断——无论是否已发内容：
落库 502（保留 usage 与空 finish）、流内写入错误事件、warn 日志
记录 provider/model/输出量。客户端由此拿到明确失败信号可干净重试。

> 2026-11-13 修正：失败路径改为调用编码器 `Abort()`，**不再补写 `[DONE]`**；
> 早期「错误事件后再 [DONE]」仍会让客户端把截断读成完成，违反同一红线。

**教训**：P0-7 修复时只验证了 CC 路径的截断（适配器层报错）；
「编码器干净 EOF + 无 finish」是另一条到达同一谎言的路径。
红线判定必须放在协议无关的 relay 层，并为每条编码路径各立回归测试。

## 3. 中优先级问题（P1）

### P1-1 首次使用引导缺失

06 文档 §7 要求首启展示三步接入引导卡，实际只有一句空状态文案：

- `internal/desktop/pages_monitor.go:34-38` 供应商健康度为空时只显示
  「还没有供应商 / 到「供应商」页新建一个，或通过 HTTP API 创建」；
- 没有第 1/2/3 步、没有可点击的「新建供应商」，也不显示客户端应指向的 Base URL。

**建议**：首页在 `providers == 0` 时展示引导卡（新建供应商 / 创建客户端密钥 / 复制服务地址），
三步文案直接引用真实端点。

### P1-2 空状态没有"下一步动作"按钮

06 文档 §7 明确要求每个列表页空状态给出下一步动作。现状：

| 页面 | 空状态文案 | 可点击动作 |
| --- | --- | --- |
| 供应商 | 先建一个供应商… | 无 |
| 模型 | 点「添加模型」或「从上游拉取」 | 文案提到，但按钮在页头 |
| 路由模型 | 点「新建路由模型」 | 文案提到，但按钮在页头 |
| 凭据 | 在供应商页添加… | 无跳转 |
| 客户端密钥 | 下游工具用 sk-prune-*… | 无 |

**建议**：空状态卡片内直接放主按钮；凭据页给出「前往供应商页」。

### P1-3 请求日志页面向 06 文档缩水

06 §3.2 承诺：端点/状态/供应商/模型/客户端密钥/时间范围六类过滤、实时尾巴开关、
行详情抽屉、表格含密钥列。现状（`pages_monitor.go:137-231`）：

- 只有端点、状态两个过滤器；
- 没有实时开关（虽然有后台轮询）；
- 选中行没有任何详情；
- 表格没有供应商、客户端密钥列；
- 顶部「6 条」没有显示"已加载/总数"，200 条上限没有"加载更多"。

**建议**：本轮至少补齐「行详情 + 已加载/总数 + 加载更多 + 实时开关」，
供应商/密钥筛选与时间范围下一轮做（需要数据面查询参数，属契约改动）。

### P1-4 总览健康度表不可点击

06 §3.1 写"点击行 → 跳 `/providers?id=`"。`pages_monitor.go:46-48` 与
`providerHealthRow`（`:77-88`）没有 `Clicked()`，整行是死的。

**建议**：整行可点，跳到供应商页并选中对应行。

### P1-5 图表不可读数，24h 柱状图浪费了错误数据

- `pages_monitor.go:91-134`：柱子没有 tooltip，无法知道某一小时的具体请求数；
- `HourBucket` 有 `Errors`、`Cost` 字段（`internal/store/types.go:245-253`），
  但图表只画 `Requests`，错误完全不可见；
- 只有"合计/峰值/首尾时间"，没有图例；
- Token 趋势（`:345-434`）同样没有逐日悬停值。

**建议**：柱子加 Tooltip（时间、请求、错误、费用）；24h 图表叠加 Danger 错误段与图例；
Token 趋势逐日显示输入/输出。

### P1-6 不可路由原因直接暴露后端英文

界面文案是中文，但状态药丸里出现 `provider has no active credential`，
在供应商表被截断成 `provider has no active credit…`，也没有 tooltip。

**证据**

- `internal/admin/common.go:140-155` 返回英文原因；
- `pages_monitor.go:86`、`pages_gateway.go:81`、`:435-437` 直接展示；
- `widgets.go:70-80` 的 `routablePill` 没有 `Tooltip`。

**建议**：桌面端做展示层映射（供应商停用/无可用凭据/模型停用/供应商缺失），
未知原因回退原文；药丸加 Tooltip 展示完整原因。

### P1-7 设置页没有脏状态与字段校验

- `settingsDirty` 字段声明了但从未使用（`state.go:77`）；
- 端口非法时静默沿用旧值（`state.go:1301`），在途上限解析失败时静默丢弃（`:1304`）；
- 保存后若无需重启才 `reloadQuiet`，用户无法确认哪些值真的生效；
- 「重新载入」会直接丢弃未保存修改，没有确认。

**建议**：字段变更置脏、页头显示「未保存」；保存前校验端口/保留天数/在途上限并给出
页面内错误；重新载入在有脏数据时二次确认。

### P1-8 客户端密钥缺少编辑能力

06 §3.8 的表格列包括允许模型数、允许 IP、额度、过期时间，但桌面端只读展示，
用户只能通过 HTTP API 修改。创建表单也只有名称。

**建议**：下一轮补「编辑密钥」弹窗（额度、允许模型、允许 IP、过期），复用
`admin.Service.UpdateClientKey`。

### P1-9 端点页把路线图写进用户界面

`pages_gateway.go:1035` 显示「自定义端点通过 HTTP API 创建；界面在后续版本补表单」。
这是内部排期，不应出现在产品界面；端点页也没有任何新建/编辑入口。

**建议**：要么本轮补最小表单，要么改为中性说明「自定义端点当前通过管理 API 创建」。

### P1-10 文档承诺的导航快捷键与命令面板缺席

06 §6 承诺 `Ctrl/Cmd + K` 命令面板、`Ctrl/Cmd + R` 刷新、`Ctrl/Cmd + 1..9` 跳页、
`Esc` 关闭。现状只有 `Esc` 由 `ui.Modal` 提供；没有 `palette.go`，没有快捷键注册
（`view.go` 全文无 `OnShortcut`）。

**建议**：本轮补 `Cmd+R`、`Cmd+1..9` 与轻量命令面板（跳页/新建供应商/刷新）；
分组折叠与自适应导航下一轮。

### P1-11 键盘可访问性不完整

侧栏 `navRow` 设置了 `Focusable()`（`view.go:144`），但只有 `Clicked()` 会切页
（`:164-166`），Enter/Space 不生效；可点击的健康度行、卡片标题也没有键盘等价物。

**建议**：聚焦行监听 Enter/Space；可点击行加 `Cursor(Pointer)` 与焦点样式。

## 4. 低优先级问题（P2）

1. **术语混杂**：`BaseURL`、`SSE`、`SQLite`、`P2`、`API` 与中文混排；价格没有货币符号
   （`pages_gateway.go:420-422`）。建议统一为「基础地址 / 流式 / 优先级 2」，
   价格加 `$` 或明确单位。
2. **KPI 行在最小宽度下偏挤**：6 个 `statTile` 不换行（`pages_monitor.go:21-28`），
   窗口最小 960 时文字可能被迫截断；`statTile` 的色点是纯装饰，没有语义标签。
3. **详情面板信息行不折行**：`infoRow` 的值 `SingleLine()` 且无 Tooltip
   （`pages_gateway.go:1041-1047`），长 BaseURL/数据目录会被截断。
4. **页脚与侧栏底部重复**：都显示服务地址与存储状态（`view.go:53-79`、`:169-186`），
   信息重复但可接受；若腾空间可去掉侧栏底部一行。
5. **表格空态与加载态**：表格加载前显示空表头，没有骨架/「加载中」；数据为空时
   表格与空状态卡并存（部分页面已避免）。
6. **模型卡片价格/上下文两行灰字密度高**：`pages_gateway.go:418-429`，可改为带图标
   的紧凑两列。
7. **日志表格宽度**：固定列宽合计约 810+（`pages_monitor.go:178-189`），
   1280 窗口可用；960 最小宽度会挤压/裁剪，且表格不支持横向滚动。
8. **删除类菜单项没有危险色**：`rowActions` 菜单里「删除」与「编辑」同色
   （`widgets.go:117-119`），建议 Danger 文字或分隔更明显。
